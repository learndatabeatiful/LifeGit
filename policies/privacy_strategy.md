# 隐私策略

## v0.1 原则

> 用户手动声明脱敏项优先；未声明的信息默认不脱敏；发送给大模型前必须明确提醒并确认。

LifeGit v0.1 不追求成为完美的自动 PII 识别器。真实测试阶段，更安全、也更容易理解的 MVP 是：让用户手动声明要脱敏的内容，展示强提醒，并保留审计记录。

## 面向用户的提醒

处理真实回忆前，展示：

```markdown
下面请您手动说明希望脱敏的名字/信息，比如：张三；洛阳市第二外国语学校。

请注意！未被列入脱敏清单的信息，v0.1 默认不会主动脱敏，后续可能会被发送给大模型处理。请注意个人隐私保护！
```

## v0.1 流程

1. **在本地收集原始回忆**。
2. **请用户提供手动脱敏清单**。
3. **展示隐私提醒**：未列入清单的信息默认保留，后续可能会被发送给模型处理。
4. **用稳定 token 替换用户明确声明的内容**。
5. **用正则/模式检查标记明显高风险秘密**。
6. **在模型推理前，请用户确认脱敏文本**。
7. **确认后只基于脱敏文本进行推理**。
8. **最终私密输出中，仅还原用户允许还原的字段**。

## 模式

| 模式 | 默认？ | 含义 |
| --- | --- | --- |
| `manual` | 真实 v0.1 测试默认 | 只替换用户声明的内容，同时标记明显高风险秘密。 |
| `light` | 可选 | Agent 辅助脱敏姓名、电话、身份证、精确地址、凭据。 |
| `medium` | 可选 | Agent 进一步建议脱敏公司、学校、同事、老师等信息。 |
| `heavy` | 可选 | Agent 泛化大部分可识别实体。 |

## 手动脱敏示例

用户可以提供：

```text
张三
洛阳市第二外国语学校
XX 科技有限公司
王老师
阳光花园小区
```

可替换为：

- `PERSON_001`
- `SCHOOL_001`
- `ORG_001`
- `TEACHER_001`
- `PLACE_001`

## 重要提醒

Manual 模式更容易理解，但保护性更弱。Agent 不能暗示隐私已得到保证，必须清楚说明：

- 未列入清单的信息默认保留。
- 明显手机号、邮箱、身份证、银行卡、密码等会被检查或提醒。
- 真实姓名、学校、公司、地点可能需要用户自己判断。
- 用户应在继续前检查脱敏文本。

## 输出要求

每次隐私处理都应输出：

```json
{
  "privacy_level": "manual",
  "user_redaction_list": [],
  "sanitized_text": "...",
  "privacy_map": {
    "entries": [],
    "kept_unredacted_items_notice": "未列入脱敏清单的信息默认保留。",
    "high_risk_warnings": [],
    "audit_notes": []
  },
  "confirmation_required": true
}
```
